**A build from this isolated worktree still declares app and CLI symlinks into
`~/nixos`.** This intentionally preserves the original ownership architecture;

the reviewed sources, those directory targets and the bridge must be aligned

performed here. Never use the existing `~/.local/bin/theme` to select the repair

This is documentation for a future manual action, not a command executed against

## Missing outputs and initialization limits

- Fuzzel reports a missing include and refuses startup. It does not reconstruct
  or overwrite its configuration. Initialize manually before using the launcher.
- Kitty logs the missing include, keeps its non-color preferences and falls back
  to default colors. Dunst keeps its original main settings and warns about the
  missing color drop-in. Its fixture process cannot reach any real display/bus.
- Hyprland uses its original palette when cached Lua is absent. Quickshell has a
  built-in palette and retains its last valid colors on malformed JSON.
- Engine include checks fail explicitly for missing Kitty/Fuzzel/Dunst outputs,
  both before initialization and after simulated cache loss.
- Init creates missing outputs, restores snapshots and removes the known invalid
  historical Dunst urgency `separator_color` property from generated output.
  It does not reload apps, change wallpapers, overwrite app configs or validate
  arbitrary pre-existing cache corruption. Existing valid outputs are retained.
- Out-of-store source edits can affect applications immediately. A Nix generation
  rollback alone cannot restore those mutable files, theme definitions or state.

source additions were already known to the index when this review began; the
remaining new report and tests are not imported by the flake.
